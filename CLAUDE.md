## Project Overview

Secure video streaming solution using JWT tokens validated at CloudFront edge locations via Lambda@Edge. Users authenticate through Cognito, receive a JWT access token, and the React frontend appends it to every HLS video segment request. Lambda@Edge validates the token before CloudFront serves content from S3.

## Commands

```sh
npm install              # Install root (frontend) dependencies
npm start                # Start React dev server (localhost:3000)
npm run build            # Production build

# Full deployment (requires amplify CLI configured)
npm run deploy           # amplify push x2 → post-deploy → upload-demo → wait for CloudFront

# Individual deployment steps
amplify push             # Deploy Cognito + Lambda + CDK stack
npm run post-deploy      # Regenerate src/deployment-config.js with CloudFront URLs
npm run upload-demo      # Sync demo/video/hls/ to S3
npm run cleanup          # Remove Lambda@Edge + IAM role, then amplify delete
```

No test suite or linter is configured.

## Architecture

### Token Flow

1. **Frontend** (`src/components/App.js`): `withAuthenticator` HOC wraps the app. After Cognito sign-in, `fetchAuthSession()` retrieves the access token (RS256 JWT).
2. **Player** (`src/components/playerjs/Player.js`): `videojs.Vhs.xhr.beforeRequest` hook appends `?token=<jwt>` to every HLS segment/manifest request.
3. **Lambda@Edge** (`amplify/backend/function/jwtauth/src/index.js`): Runs on `viewer-request` event. Validates JWT signature against pre-baked JWKS keys using native `crypto.createPublicKey` (JWK format) + `crypto.createVerify('RSA-SHA256')`. Checks issuer, `token_use === 'access'`, expiration, then strips the token from the query string before forwarding to S3.

### Infrastructure (CDK)

`amplify/backend/custom/customResource2bc9d7e6/cdk-stack.ts` defines:
- S3 bucket (`secure-media-{AccountId}-{env}`) with block-all-public-access
- CloudFront distribution with Origin Access Control (OAC, SigV4)
- Bucket policy scoped to the distribution's ARN

The CDK stack uses L1 `CfnDistribution` (not the higher-level `Distribution` construct) for full control over cache behavior and Lambda@Edge associations.

### Deployment Pipeline

`amplify/hooks/post-push.js` runs after `amplify push` and:
- Queries CloudFormation for Cognito user pool ID
- Fetches JWKS from Cognito's `.well-known/jwks.json` endpoint
- Writes `config.js` with region, user pool ID, and JWKS JSON
- Downloads the Amplify-deployed Lambda, re-deploys it to us-east-1 as Lambda@Edge
- Publishes a version and associates it with the CloudFront distribution's `viewer-request`

### Key Files

- `amplify/backend/function/jwtauth/src/config.js` — auto-generated by post-push hook; contains Cognito region, user pool ID, and JWKS (baked into the Lambda package)
- `amplify/hooks/lambda-edge-function.js` — alternative JWT validation implementation using `jsonwebtoken` library and manual JWK-to-PEM conversion (not the primary deployed version)
- `src/deployment-config.js` — auto-generated by `scripts/update-frontend-config.js`; contains CloudFront distribution URL and S3 bucket name

### Token Validation Requirements

- RS256-signed JWT with 3 dot-separated base64url parts
- Issuer must match `https://cognito-idp.{REGION}.amazonaws.com/{USERPOOLID}`
- `token_use` claim must be `"access"`
- `kid` header must match a key in the pre-baked JWKS
- `exp` must be in the future
